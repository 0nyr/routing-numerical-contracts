For static v0.13, we recommend ranking incumbents by the authoritative checker value while retaining canonical route ordering for storage. Candidates and incumbents should be validated and repriced in that same stored order before comparing their objective keys, preserving the fleet tier where applicable. This removes the separate exact-decimal ranking objective while keeping deterministic storage and candidate-validation repairs. It restores checker-aligned ranking, not every detail of the 0.11 storage policy. Historical declared values remain attached to their original serialized route order. Canonicalization does not make sequential addition order-independent, and route reversal or a different arc multiset can still distinguish exact-decimal ties. The rational sums remain available as diagnostics rather than a second authoritative BKS objective.
